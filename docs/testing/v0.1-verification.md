The PGlite Auth shim does not validate the real Supabase Auth service, PostgREST or Storage.

`scripts/verify-live-auth.mjs` checks real Supabase Auth/PostgREST: effective Auth settings, invalid password rejection, unprovisioned access, password login, owner branch visibility, foreign-branch isolation, denied role mutation, refresh/session identity, membership revocation/restoration, anonymous denial, disabled public signup and refresh-token revocation after sign-out. These checks passed in [Database CI on `0c6820a`](https://github.com/GnaneswarRaju/SriNidhi/actions/runs/36167162295). The first runs exposed a real local configuration error: `[auth.email].enable_signup=false` disabled the email provider, returning HTTP 422. Merely accommodating a different rejection status did not fix it. The provider is now enabled, global public registration remains disabled, and invalid passwords must return HTTP 400 with `invalid_credentials` and no token. Error codes are read from the supported `error_code`/`code` envelopes. Disposable local fixtures are discarded with the CI stack.

Screenshots in `docs/design/screenshots/` use clearly synthetic **test-only** accounts and branches. They are not evidence of hosted authentication or live store data. The initial screenshot helper needed real asynchronous font/image work and explicit Material icon font loading; both were fixed before final captures. The local preview's root-path check was corrected and verified with HTTP 200 and a browser render.

The web compiler reports an optional Cupertino icon font warning; this foundation uses Material icons, which were verified in rendered previews and the release setup screen. Native adaptive controls still need device validation. The compiler's Wasm dry run passed, but the shipped/tested target is the default JavaScript release build.
